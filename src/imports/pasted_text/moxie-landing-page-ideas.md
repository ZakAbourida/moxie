Attualmente parti subito con Moxie.
Manca un momento in cui il coach pensa:
"Sì. È esattamente il mio problema."
Prima del Hero o immediatamente dopo il Hero metterei una sezione molto breve tipo:
Coaching shouldn't live in spreadsheets.
E mostrerei il problema visivamente:
Programmazione Excel / Sheets / note / WhatsApp
↓
Allenamento
↓
Feedback
↓
Decisioni
ma tutto scollegato.
Poi:
Moxie connects them.
Il punto non è dire "Excel fa schifo".
È mostrare che il problema è la frammentazione del processo decisionale.
Questo è il vero problema che Moxie risolve.

2. Una sezione "How Moxie actually works"
Hai il loop nella Hero, ma secondo me merita un approfondimento autonomo.
Perché il loop è praticamente il core product model.
Potrebbe essere:
01 — Plan
Il coach costruisce il programma.
02 — Execute
L'atleta registra ciò che è successo realmente.
03 — Measure
Moxie raccoglie performance, readiness, carichi e feedback.
04 — Decide
Il coach modifica la programmazione sulla base dei dati.
E poi ritorna a:
Plan → Execute → Measure → Decide → Plan
Questo è più interessante delle singole feature perché comunica il sistema.

3. Una vera sezione "Built for performance”
Questa per me è importante soprattutto considerando il posizionamento di Moxie.
Moxie non dovrebbe sembrare:
"un'altra app per fitness/coaching."
La landing deve far capire immediatamente che esiste una comprensione specifica del lavoro del coach.
Per esempio:
Built for real performance coaching.
Track & field specific data
* training loads 
* throws volume 
* intensity 
* readiness 
* competition planning 
* performance trends 
Il vantaggio competitivo potrebbe essere proprio:
Not built for everyone. Built for coaches who care about performance.
Non generic fitness.
Non "personal trainer app".
Non habit tracker.

Il problema principale della landing attuale
Non è una mancanza di contenuti.
È il rischio di avere una struttura:
Feature → Feature → Feature → Graph → Feature → Graph → Comparison
che comunica:
"Moxie ha tante funzionalità."
Mentre il messaggio che dovrebbe passare è:
"Moxie cambia il modo in cui un coach prende decisioni."
Questa differenza è enorme.
La landing dovrebbe quindi avere tre livelli narrativi:
1. Problema Il coaching è frammentato.
2. Sistema Moxie crea il loop: Plan → Execute → Measure → Adapt
3. Prova Ecco il prodotto, ecco i dati, ecco cosa succede in casi reali.
Le feature diventano la dimostrazione del sistema, non il contenuto principale della pagina.
Una cosa che renderei molto evidente
Moxie non dovrebbe vendersi come:
"software per programmare allenamenti."
È troppo debole e ti mette direttamente contro decine di strumenti.
Il posizionamento più interessante che emerge dalla landing è invece qualcosa vicino a:
Moxie is a coaching operating system for performance.
oppure:
The operating system for data-driven coaching.
oppure, ancora più specifico:
Where training plans become coaching decisions.
Quest'ultimo concettualmente è molto forte perché riassume quasi tutto ciò che stai costruendo
